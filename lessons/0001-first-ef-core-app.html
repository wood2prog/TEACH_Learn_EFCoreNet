Lesson 1: Your First EF Core App

⏱ ~20 min .NET 10EF Core 10

Mission link: You want to be able to work on .NET projects using EF Core. This lesson gets you from "I've read about it" to "I've built it." Every future lesson builds on this foundation.

What you'll learn

  • Scaffold a .NET console project
  • Add the EF Core SQLite NuGet package
  • Define an entity class and DbContext
  • Create and apply a migration
  • Write, read, update, and delete data

1. Create the project

Open a terminal and run:

dotnet new console -n BookApp cd BookApp

Open the project in your editor. This is a blank .NET project — we'll add EF Core to it.

2. Install the EF Core SQLite provider

EF Core uses a provider model. Each database type (SQL Server, SQLite, PostgreSQL, etc.) has its own provider package. We'll use SQLite — zero setup, runs everywhere.

dotnet add package Microsoft.EntityFrameworkCore.Sqlite dotnet add package Microsoft.EntityFrameworkCore.Design

Why two packages? Sqlite is the database driver. Design provides the dotnet ef tooling (migrations, scaffolding). You need both.

Also install the dotnet-ef global tool if you haven't already:

dotnet tool install --global dotnet-ef

3. Define a model

Create a file Book.cs:

public class Book
{
    public int Id { get; set; }
    public string Title { get; set; } = string.Empty;
    public string Author { get; set; } = string.Empty;
    public int PublicationYear { get; set; }
    public decimal Price { get; set; }
}
Convention: EF Core automatically treats a property named Id or <EntityName>Id as the primary key. No attributes needed — that's the convention over configuration philosophy.

4. Create a DbContext

The DbContext is your session with the database. It coordinates querying, saving, and tracking changes. Create BookContext.cs:

using Microsoft.EntityFrameworkCore;

public class BookContext : DbContext
{
    public DbSet<Book> Books { get; set; }

    protected override void OnConfiguring(DbContextOptionsBuilder optionsBuilder)
    {
        optionsBuilder.UseSqlite("Data Source=books.db");
    }
}

Note: Hardcoding connection strings is fine for a console app. In production apps (ASP.NET Core), you'd register the context via DI and read the connection string from configuration. We'll cover that later.

5. Create and apply a migration

Migrations translate your C# model into database schema. Run:

dotnet ef migrations add InitialCreate

This creates a Migrations folder with two files: a snapshot (tracks your model) and a migration (the SQL to create tables). Look at them — they're just C#.

Now apply the migration to create the actual database:

dotnet ef database update

You should now see books.db in your project folder. That's your SQLite database.

6. Write some CRUD code

Replace Program.cs with:

using Microsoft.EntityFrameworkCore;

// Create
using var db = new BookContext();
db.Database.EnsureCreated();

db.Books.Add(new Book
{
    Title = "Domain-Driven Design",
    Author = "Eric Evans",
    PublicationYear = 2003,
    Price = 49.99m
});
db.SaveChanges();
Console.WriteLine("✅ Book inserted!");

// Read
var books = db.Books
    .Where(b => b.PublicationYear > 2000)
    .OrderBy(b => b.Title)
    .ToList();

Console.WriteLine($"\nBooks ({books.Count} found):");
foreach (var book in books)
{
    Console.WriteLine($"  {book.Title} by {book.Author} — ${book.Price}");
}

// Update
var bookToUpdate = db.Books.First();
bookToUpdate.Price = 39.99m;
db.SaveChanges();
Console.WriteLine($"\n✅ Updated price to ${bookToUpdate.Price}");

// Delete
db.Books.Remove(bookToUpdate);
db.SaveChanges();
Console.WriteLine("✅ Book deleted!");

Run it:

dotnet run

You should see:

✅ Book inserted!

Books (1 found):
  Domain-Driven Design by Eric Evans — $49.99

✅ Updated price to $39.99
✅ Book deleted!

  3. Apply it: dotnet ef database update

  5. Run the app and confirm it works

Extra: Query books filtered by genre.

Key takeaways

  • Entity class → table. Properties → columns. Conventions (like Id → PK) reduce boilerplate.
  • DbContext is your bridge between C# and the database. You expose entities via DbSet<T> properties.
  • Migrations are version-controlled C# files that evolve your schema. Create them with dotnet ef migrations add, apply them with dotnet ef database update.
  • CRUD is just LINQ + SaveChanges(). EF Core tracks changes and generates the SQL automatically.
