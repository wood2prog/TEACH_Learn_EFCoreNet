EF Core Glossary

Common terms and concepts used throughout these lessons.

Entity
A C# class that maps to a database table. Properties map to columns. Instances are rows.
Example: A Book class becomes a Books table.
DbContext
The primary class that coordinates database operations. Represents a session with the database. Exposes entities via DbSet<T> properties and manages change tracking, connection, and transactions.
DbSet<T>
A property on a DbContext that represents a collection of entities. Used to query (LINQ) and add/remove entities. Maps to a database table.
Migration
A C# file that describes schema changes (create table, add column, etc.). Generated by dotnet ef migrations add. Applied with dotnet ef database update. Version-controlled.
Provider
A NuGet package that lets EF Core talk to a specific database (SQLite, SQL Server, PostgreSQL, Cosmos DB, etc.). Example: Microsoft.EntityFrameworkCore.Sqlite.
Convention
Default behavior EF Core applies based on naming patterns. Example: A property named Id becomes the primary key automatically. You only need to override conventions when your model deviates from them.
Fluent API
Configuration code written in OnModelCreating to override conventions. More powerful than data annotations. Example: modelBuilder.Entity<Book>().Property(b => b.Title).HasMaxLength(200).
Data Annotation
Attributes on entity classes/properties that configure mapping. Example: [Required], [MaxLength(200)], [Key]. Less powerful than Fluent API but simpler.
Navigation Property
A property on an entity that points to a related entity (or collection). Enables EF Core to load related data. Example: public Author Author { get; set; } or public ICollection<Book> Books { get; set; }.
Change Tracking
The mechanism by which EF Core monitors entity instances and detects changes. When you call SaveChanges(), EF Core generates SQL for only what changed.
SaveChanges()
The method that persists all pending changes to the database. Returns the number of rows affected. Wraps operations in a transaction.
LINQ (Language Integrated Query)
C# syntax for querying data. EF Core translates LINQ expressions into SQL. Example: db.Books.Where(b => b.Year > 2000).OrderBy(b => b.Title).
Eager Loading
Loading related data upfront using .Include(). Example: db.Books.Include(b => b.Author). Prevents N+1 query problems.
Explicit Loading
Loading related data on demand after the parent entity is already loaded. Uses .Entry().Reference() or .Collection().Load().
Lazy Loading
Navigation properties loaded automatically when accessed. Requires a proxy package. Opt-in. Can cause N+1 issues if not careful.
N+1 Query Problem
A performance anti-pattern where EF Core executes one query for the parent and then N queries for each child. Prevented by using .Include() (eager loading).
AsNoTracking()
A query method that disables change tracking for read-only scenarios. Improves performance and reduces memory usage. Example: db.Books.AsNoTracking().ToList().
Shadow Property
A property in the EF model that doesn't exist in the C# class. Commonly used for foreign keys and timestamps. Managed automatically by EF Core.
Connection String
A string that tells EF Core where the database is and how to connect. Example (SQLite): Data Source=books.db. Example (SQL Server): Server=.;Database=MyDb;Trusted_Connection=True.
Code First
An approach where you write C# classes first, then generate the database schema from them via migrations. The modern EF Core approach.
Database First
An approach where you have an existing database and reverse-engineer C# classes from it. Uses dotnet ef dbcontext scaffold.
